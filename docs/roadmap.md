# PickDeal 남은 작업

> 갱신: 2026-09-27
> 미해결 작업과 보류 판단만 관리한다. 완료 이력은 Git, 계약은 `docs/01~06`, 조사 근거는 `docs/notes/`를 따른다. 구현 현황과 설계 규칙을 여기 반복하지 않는다.

## 현재 우선순위

- 기능 추가와 UI/UX 개선을 우선한다. 구체적인 작업은 실제 사용 불편과 요청을 기준으로 정한다.
- 더 보기에서 다음 페이지를 받는 사이 새 Deal이 수집되면 offset이 밀려 같은 카드가 다시 보일 수 있다. 재현을 확인한 뒤 프론트 중복 제거 또는 cursor 페이지네이션(`docs/03` 6장)으로 처리한다.

## 필요가 확인되면 다시 판단할 것

- 운영 실행 커밋·출처별 최근 수집 로그·중복 스케줄러 여부·백업 및 테스트 DB 복구·DNS(deSEC) 자동 갱신 수단 확인은 추후 작업으로 보류한다. 구성·검증 절차는 `docs/06`을 따른다.
- 재수집 시 썸네일 갱신은 도입하지 않는다. 신규 저장 시 URL을 저장하는 현재 방식을 유지한다.

- 알림: 상시 수집이 안정된 뒤 한 채널만 선택한다. 동작하지 않던 알림·프로필 데모 UI는 제거했으며 알림 기능을 만들 때 다시 추가한다. 남은 AI UI의 유지 여부는 별도로 결정한다.
- AI 댓글 요약: 댓글 확보 가능성과 요청·저장 비용을 먼저 확인한다.
- 서버 worker 분리·Redis: 조회량·응답 시간·수집 지연 등 실제 병목을 근거로 검토한다. 목록 조회 병목은 DB 처리로 해소했다(2026-10-27, notes C-3 후속 2).
- 검색어 부분 일치 인덱스(`pg_trgm`): 검색이 가장 느린 경로다(30,000건 동시 10명 p95 605ms, 운영 규모 약 30ms). 운영 지표에서 검색 지연이 확인되면 검토한다.
- 인증·멀티유저: 공개 쓰기 기능과 사용자별 데이터 격리가 필요할 때 별도 범위를 정한다.
- 가격 이력은 제외 상태를 유지하며, 관심 없음 등 추가 개인화는 반복되는 사용 불편이 확인될 때 검토한다.
