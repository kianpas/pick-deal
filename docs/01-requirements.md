# 01. 요구사항 정의서 (Requirements)

> PickDeal — 개인용 핫딜 큐레이션 서비스
> 본 문서는 이후 구현 작업의 기준 문서입니다. 모든 설계 문서(`docs/01` ~ `docs/06`)는 상호 참조됩니다.
> 최초 작성: 2026-05-20 · 현재 상태 갱신: 2026-09-05
> 현재 단계: 핵심 조회·설정 MVP와 복수 출처 자동 수집, 교차 출처 DealGroup 연결 및 목록·상세 노출까지 진행됐다. 현재 출처와 판정 규칙은 `docs/05`를 따른다.

## 1. 프로젝트 목적

PickDeal은 여러 커뮤니티/사이트에 흩어져 있는 핫딜 정보를 한곳에 모아, **사용자가 원하는 출처와 키워드 기준으로만 걸러서 보는** 개인용 큐레이션 서비스다.

핵심 가치는 다음과 같다.

- **집중**: 관심 없는 출처/상품을 숨기고, 관심 키워드 중심으로만 본다.
- **소음 제거**: 제외 키워드로 광고성·관심 밖 딜을 걸러낸다.
- **확장 가능성**: 초기에는 단순 조회/필터에서 시작하되, 수집 자동화·중복 제거·댓글 요약·알림·AI 구매 판단 보조까지 단계적으로 확장한다.

본 프로젝트는 **단일 사용자(개인)** 사용을 전제로 시작한다. 인증/회원 개념은 MVP에 두지 않되, 데이터 모델에는 향후 멀티유저 확장을 위한 여지를 남겨둔다(아래 5장 참고).

## 2. 해결하려는 문제

| 문제 | 현재 상황 | PickDeal의 접근 |
| --- | --- | --- |
| 정보 분산 | 핫딜이 여러 커뮤니티/사이트에 흩어져 있음 | 여러 출처의 딜을 한 화면에 모아 조회 |
| 노이즈 | 관심 없는 카테고리·출처·광고성 딜이 섞임 | 출처 표시/숨김 + 관심/제외 키워드 필터 |
| 중복 | 같은 딜이 여러 출처에 중복 게시됨 | 강한 근거가 같은 교차 출처 Deal을 그룹으로 연결하고 원본 보존 |
| 판단 비용 | "이거 살 만한가?"를 매번 직접 판단 | (3차) 댓글 반응 요약 + AI 구매 판단 보조 |
| 놓침 | 관심 딜을 실시간으로 못 봄 | (2차) 관심 키워드 알림 |

현재는 정보 분산과 노이즈를 기본으로 해결하고, 보수적인 교차 출처 그룹까지 구현했다. 판단 보조와 놓침 방지는 실제 운영 데이터가 쌓인 뒤 다룬다.

## 3. MVP 기능 범위

> 핵심 조회·설정 MVP는 더미 데이터로 시작했으며, 현재는 **복수 출처 자동 수집과 보수적인 교차 출처 그룹의 목록·상세 노출까지 구현**됐다.
> AI 요약, 알림, 별도 worker는 여전히 범위 밖이다.

### 3.1 기능 목록

1. **핫딜 목록 조회**
   - 등록된 딜 목록을 페이지네이션으로 조회한다.
   - 출처 필터, 관심/제외 키워드 필터, 정렬(최신순/할인율순)을 지원한다.
   - 자유 검색어 `q`는 공백으로 단어를 나누고 대소문자를 무시한다. 모든 단어가 같은 원본 게시글의 제목 또는 저장된 본문에 포함되어야 하며, 그룹의 서로 다른 게시글에 나뉘어 있는 단어를 합쳐 일치시키지 않는다. 등록된 관심·제외 키워드는 기존의 문자열 포함 규칙을 유지한다.
   - 공개 목록의 커뮤니티 조회 필터는 URL의 반복 `sourceId`로 여러 출처를 선택한다. 미선택은 전체이며 검색·카테고리·더 보기에도 유지한다. DB의 출처 표시 설정을 변경하지 않으며 숨김 출처를 다시 노출하지 않는다.
   - PC·모바일에서 동일한 커뮤니티 조회 필터를 제공한다.
   - `종료·품절 숨기기`는 기본 OFF이며 URL `hideEnded=true`로 선택한다. 저장된 상태만 사용하고 외부 사이트를 추가 조회하지 않는다. 표시 출처·쇼핑몰 조건을 통과한 그룹 구성원이 모두 종료/품절이면 제외하며 페이지 분리 전에 적용한다. 검색·다른 필터·더 보기·상세의 목록 복귀에 유지하고 전체 초기화 시 해제한다. 적용 중 기존 목록과 진행 안내를 표시하며 더 보기는 잠시 비활성화한다. 상태 미수집 출처나 재수집 범위를 벗어난 글의 실제 판매 여부까지 보장하지 않는다.
   - 카테고리는 저장된 출처 분류를 보존하고 조회 시 8개 픽딜 분류로 통합한다(`docs/03` §2.2). URL 필터는 새 코드만 사용하며 기존 분류명 URL은 지원하지 않는다. 미등록·미분류는 기타로 표시하고 상세에는 출처 분류를 함께 표시한다.
   - 목록 상단에 적용 중인 검색·카테고리·쇼핑몰·커뮤니티 조건을 표시하고 개별 해제 및 전체 초기화를 제공한다. 쇼핑몰 검색은 선택지 목록만 좁히며 이미 선택한 조건은 유지한다.
   - `검색·필터 초기화`는 검색·카테고리·쇼핑몰·커뮤니티·종료 숨기기 중 하나만 적용되어도 표시한다. 초기화는 해당 URL 조건과 페이지·복귀 표식 및 목록 스냅샷을 제거하며 DB의 관심·제외 키워드와 출처 표시 설정은 변경하지 않는다. 빈 결과 화면에서도 동일하게 처리한다.
   - 빈 목록은 조건 적용 여부에 따라 조건에 맞는 결과 없음 또는 현재 표시할 결과 없음으로 안내하며 미수집·수집 예정으로 단정하지 않는다. 조회 실패는 별도 오류 안내와 재시도를 제공한다. 설정 변경이 허용된 모드에서만 저장된 키워드·출처 설정 안내와 키워드 관리 링크를 표시한다.
   - 목록에서 상세로 이동한 뒤 '목록으로'를 누르면 검색·카테고리·복수 쇼핑몰·복수 커뮤니티 조건과 더 보기로 펼친 목록·스크롤 위치·썸네일 표시를 유지한다. 같은 탭의 sessionStorage에 화면 스냅샷 1개를 최대 15분간 저장하고 복귀 시 한 번 사용한다. 선택 상품 링크로 키보드 포커스를 복원하며 화면 너비가 바뀌면 해당 상품 위치로 이동한다. 필터가 다르거나 저장소가 차단/초과/만료되면 첫 페이지로 돌아간다. 출처 표시 설정 변경 시 스냅샷을 폐기한다. 이는 화면 복귀용 임시 데이터이며 DB 설정이나 최신 수집 상태의 근거가 아니다. 상세 직접 진입 시에는 전체 목록으로 이동한다.
   - 목록에서 선택한 썸네일 표시 여부는 검색·커뮤니티·쇼핑몰·카테고리 조건을 변경해도 유지한다. 조건이 바뀌면 목록과 더 보기 페이지 상태만 초기화한다. 보기 설정은 현재 목록 화면의 메모리 상태이며 새로고침 후에는 기본값(표시)으로 돌아간다.
   - 쇼핑몰 필터는 DB의 표시 출처에 저장된 판매처 이름 목록을 사용한다. PC는 왼쪽 사이드바, 모바일은 접이식 영역에 표시한다. URL의 반복 `shopName`으로 복수 선택하며 선택 간 OR, 커뮤니티·검색·카테고리와는 AND로 적용한다. 미선택은 전체이며 더 보기에도 유지한다. 목록과 필터에는 등록된 별칭만 통합한다(`docs/03` §2.2.1). 저장된 원문과 카드·상세의 판매처 표기는 보존하며 가상 건수·추가 버튼은 제공하지 않는다.
   - 쇼핑몰 선택지는 표시 출처의 수집 게시글 수가 많은 순(별칭 합산, 동률이면 이름순)으로 처음 6곳과 선택된 항목을 기본 표시하며, 나머지는 `N곳 더 보기`로 펼친다. 선택 시 맨 위로 재정렬하지 않는다. 검색 중에는 접기 제한 없이 일치하는 모든 선택지를 표시하고, 검색 해제 시 이전 펼침 상태로 돌아간다. 목록에서 사라진 선택값도 해제할 수 있도록 유지한다. 딜 건수는 표시하지 않으며, 미선택 안내는 `전체 쇼핑몰`로 통일한다.
   - 사용자가 "숨김" 처리한 출처의 딜은 기본적으로 목록에서 제외한다.
   - 교차 출처에서 같은 딜로 연결된 게시글은 대표 카드 하나로 표시하고 출처 수와 이름을 제공한다.
   - 목록의 진행 중 딜은 저장된 댓글 수가 20개 이상이면 숫자만 굵게 표시한다. 아이콘·색상은 유지하며 종료·품절은 강조하지 않는다. 댓글 미확인은 표시하지 않고 그룹은 대표 게시글 값만 사용한다. 추가 수집·시간 제한·인기순·추천 판정은 도입하지 않는다.
2. **핫딜 상세 조회**
   - 단일 딜의 상세 정보를 조회한다(제목, 가격/정가/할인율, 카테고리, 썸네일, 원본 링크, 출처, 게시 시각 등).
   - `링크 복사`는 현재 사이트의 픽딜 상세 주소를 공유하며 목록 복귀용 필터·해시는 포함하지 않는다. 클립보드 미지원·권한 거부 시 직접 선택할 주소를 제공한다. 공유 자체로 외부 사이트 조회나 백엔드 쓰기를 발생시키지 않는다.
   - 상세는 저장된 정보만 사용한다. 썸네일은 최대 96px 정사각 영역에서 원본보다 확대하지 않고 가격 옆에 표시한다. 구매처·원문 링크는 가격 다음에 배치하고, 판매처·수집 시각·출처 분류·수집된 댓글 수와 본문을 제공한다. 이미지가 없으면 영역을 생략하며 로딩 실패 시 같은 크기의 대체 표시를 사용한다.
   - 그룹에 연결된 경우 가격 바로 아래의 출처별 비교에서 원문 제목·판매처·가격/통화·상태·게시 시각·댓글 수·원문/상품 링크를 각각 조회한다. 상단 가격·상태는 요청한 게시글 기준임을 표시한다. 미확인 가격·댓글은 0으로 표시하지 않으며 댓글 합산·최저가 순위는 제공하지 않는다. PC는 정렬된 행, 모바일은 줄바꿈 가능한 배치로 제공한다.
3. **출처 사이트 목록 조회**
   - 등록된 출처 사이트 목록과 각 출처의 표시/숨김 상태를 조회한다.
4. **출처 사이트 표시/숨김 설정**
   - 출처별로 표시 여부를 토글한다. 설정은 백엔드 DB에 저장한다.
5. **관심 키워드 / 제외 키워드 등록·조회·삭제**
   - 관심 키워드(interest)와 제외 키워드(exclude)를 각각 등록, 조회, 삭제한다.
   - 설정은 백엔드 DB에 저장한다.

### 3.2 키워드 필터 동작 규칙 (MVP)

- 필터는 **서버 측에서** 적용한다(클라이언트 필터 아님). 목록 API가 최종 필터링된 결과를 반환한다.
- 매칭 방식은 MVP에서 **단순 포함(substring, 대소문자 무시) 검색**으로 한다. 형태소 분석/토큰화는 도입하지 않는다.
- 적용 우선순위: **제외 키워드 > 관심 키워드 > 출처 숨김**.
  - 제목/요약에 제외 키워드가 하나라도 포함되면 노출하지 않는다.
  - 관심 키워드가 1개 이상 등록되어 있으면, 관심 키워드를 포함하는 딜만 노출한다(관심 키워드가 0개면 출처/제외 기준만 적용).
  - 숨김 처리된 출처의 딜은 노출하지 않는다.
- 위 규칙은 `docs/03-api-design.md`의 목록 조회 API 동작과 일치해야 한다.

### 3.3 데이터 입력 방식

- 초기에는 코드 기반 시드 데이터로 딜·출처를 채웠다.
- 현재는 등록된 출처의 목록을 `@Scheduled`로 수집해 저장하며, 시드 데이터도 로컬 초기 데이터 용도로 유지한다.
- 필요 시 운영자가 수동으로 딜을 등록할 수 있는 **내부용 등록 API**를 둘 수 있다(관리 화면은 MVP 범위 밖, API만 선택적으로 제공). 상세는 `docs/03`, 시드 전략은 `docs/04` 참고.

### 3.4 현재 기능 범위에서 명시적으로 제외하는 것

- AI 댓글 요약, AI 구매 판단 보조
- 알림(푸시/이메일 등)
- 사용자 인증/회원가입/로그인
- Redis 사용

Dockerfile·Compose·운영 프로필·Flyway는 제품 기능이 아니라 다음 상시 배포 작업에서 다룬다. 복잡한 CI/CD는 여전히 제외한다.

## 4. 확장 기능 범위 (2차 / 3차)

> 확장 기능은 MVP와 **명확히 분리**한다. 아래 항목은 MVP 구현 대상이 아니며, 문서상 확장 방향으로만 정의한다.

### 4.1 2차 확장

- **수집기 확장**: 복수 출처 자동 수집은 구현됐다. 새 출처는 같은 공통 계약으로 추가한다(`docs/05`).
- **중복 딜 제거(dedup)**: 정규화 제목과 추가 강한 근거가 정확히 일치하는 서로 다른 출처 Deal의 자동 연결과 대표 목록·출처별 상세 UI가 구현됐다. 운영 데이터로 판정 규칙을 보정한다.
- **관심 키워드 알림**: 관심 키워드에 매칭되는 신규 딜 발생 시 알림.
- **Redis 도입**: 중복 수집 방지, 캐시, 작업 큐, rate limit 등이 필요한 시점에 추가(`docs/05` 참고).
- **collector worker 분리**: 출처 수 자체가 아니라 수집 부하가 조회 API에 영향을 줄 때 backend API와 collector 분리를 검토한다(`docs/02`, `docs/06`).

### 4.2 3차 확장

- **댓글 반응 요약**: 출처의 댓글을 수집·요약해 딜의 평판을 한눈에 제공(AI 요약 구조는 `docs/05`).
- **AI 기반 구매 판단 보조**: 가격 추이, 댓글 요약, 사용자 선호를 종합해 "지금 살 만한가"를 보조 판단.
- **멀티유저 전환**: 인증 도입 및 사용자별 설정 분리(아래 5장에서 미리 대비).

---

## 5. 사용자 모델 (MVP: 단일 사용자)

- MVP는 **인증 없는 단일 사용자**로 시작한다.
- 현재 고정 `user_id`의 설정·내부 쓰기 API는 공개 서비스에서 안전한 사용자 경계가 아니다. 최초 배포에서는 개인 접근으로 제한하거나 읽기와 쓰기 접근 범위를 분리한다(`docs/06`).
- 단, **기본 회원가입/로그인은 계획된 마일스톤**이다. 그래서 설정성 테이블(`source_visibility`, `keyword`)에 `user_id`를 두고 지금은 고정값(예: `1`)을 쓰며, 인증 도입 시 사용자 스코프로 전환한다.
- 상세 스키마는 `docs/04-database-design.md` 참고.

---

## 6. 비기능 요구사항 (NFR)

- **성능**: 목록 조회는 페이지네이션 기준 1페이지(예: 20건) 응답이 일반 트래픽에서 빠르게 반환되어야 한다(인덱스 설계는 `docs/04`).
- **확장성**: backend와 scheduler를 단일 애플리케이션으로 시작하되, collector worker 분리가 가능한 구조를 유지한다.
- **이식성**: 현재 로컬 PostgreSQL로 개발한다. 운영 준비 시 Vercel(frontend) + OCI/VPS Docker Compose(backend/DB)로 배포 가능하게 구성한다(`docs/06`).
- **유지보수성**: frontend/backend를 monorepo로 분리하고, 문서 기반으로 구현 순서를 따른다.
- **데이터 정합성**: 동일 딜 중복 저장을 막기 위한 유니크 제약(`source_id + external_id`)을 초기부터 둔다.

## 7. 용어 정의 (Glossary)

| 용어 | 정의 |
| --- | --- |
| 딜(Deal) | 하나의 핫딜 정보. 제목, 가격, 출처, 링크 등을 가진다. |
| 출처(Source) | 딜이 게시된 커뮤니티/사이트. 표시/숨김 설정의 대상. |
| 관심 키워드(Interest keyword) | 해당 키워드를 포함하는 딜만 노출시키는 화이트리스트성 키워드. |
| 제외 키워드(Exclude keyword) | 해당 키워드를 포함하는 딜을 숨기는 블랙리스트성 키워드. |
| dedup 키 | 중복 딜을 식별하기 위한 키(`source_id + external_id`, 정규화 제목 해시 등). |
| collector / worker | collector는 현재 동일 backend 앱에서 등록된 복수 출처의 딜을 수집한다. 별도 worker 분리는 향후 선택 사항이다. |
